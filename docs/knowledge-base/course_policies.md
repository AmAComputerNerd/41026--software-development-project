# Course Policies & Notification Guidelines

## 1. Subject Overview & Assessment Structure
- **Subject**: 41026 Advanced Software Development Project (Autumn / Spring 2026)
- **Credit Points**: 6 CP
- **Teaching Mode**: Integrated Studio & Microservice Architecture Laboratory

### Assessment Breakdown
1. **Release 0 (Sprint 1)**: Integrated Containerised Microservices Foundation (20%)
2. **Release 1 (Sprint 2)**: Agentic AI Extension with Local Shared MCP, RAG, and Agentic Loop (30%)
   - Release 1 Showcase and Technical Q&A held in Week 9 studio. Attendance is mandatory for all team members.
   - Deliverables: Single group technical report (`group-<number>.pdf`, max 3000 words + diagrams), integrated working software repository, and showcase video (max 10 minutes).
3. **Release 2 (Sprint 3)**: Autonomous Agent Collaboration & Final Production Release (50%)

---

## 2. Late Submission Policy
- **Standard Late Penalty**: 5% of the maximum possible mark is deducted per 24-hour period (or part thereof) following the deadline.
- **Maximum Lateness Allowed**: Work submitted more than 5 calendar days (120 hours) after the deadline receives a mark of 0%.
- **Special Consideration / Extension Requests**:
  - Extensions of up to 48 hours must be submitted via the Student Portal at least 24 hours prior to the due date.
  - Medical or exceptional circumstances require formal documentation within 3 working days of the missed assessment.

---

## 3. Notification Service Levels (SLA) & Priorities
Student 1 NotificationService categorises all system events into five distinct streams:

1. **Deadline Notifications**:
   - Sent at 24 hours and 3 hours prior to any assignment or task due date.
   - Actionable buttons: `MARK COMPLETE`, `AI BREAK DOWN` (subtasks breakdown).
2. **Grade Notifications**:
   - Dispatched immediately upon grade publication from Canvas or Student 5 GradesManager.
   - Actionable button: `GRADE IMPACT` (launches what-if simulator).
3. **Automation Notifications**:
   - Real-time status alerts for scheduled posts, quiz autofill executions, and auto-extension triggers from Student 2 Automations.
4. **Account & Security Notifications**:
   - Password reset links, profile updates, and role modifications from Student 4 Authentication.
5. **AI Broadcast & System Alerts**:
   - High-priority broadcasts dispatched via the shared Model Context Protocol (MCP) server.
   - Urgency levels: `Low`, `Medium`, `High`, `Critical`.
   - Critical urgency alerts bypass snooze preferences and display instant persistent toasts.

---

## 4. Academic Integrity & LLM Usage Rules
- OpenRouter and internal AI models are approved for architectural evaluation, task breakdown, code explanation, and automated notification summarisation.
- All code committed to the repository must be authored, validated, and defended by team members during studio demonstrations and technical Q&A.
- Every RAG response generated by the application must cite source files and report an evaluated confidence category (`HIGH`, `MEDIUM`, or `LOW`). When relevant context is absent from the corpus, an explicit `INSUFFICIENT_CONTEXT` fallback must be displayed.
